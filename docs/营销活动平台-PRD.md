## 1. 项目背景与目标

### 1.1 背景

业务方每次投放营销活动均需重复开发资格判断、发奖对接、订单管理、对账补偿等能力，交付周期长且一致性缺陷分散。本平台将「用户完成指定行为 → 获得奖励」抽象为可配置玩法，沉淀公共能力，业务方通过配置与接口接入。

### 1.2 首期范围

首期交付两种玩法及其共用底座。

| 玩法 | 用户行为 | 平台交付 | 资金方向 |
| --- | --- | --- | --- |
| 裂变 | 邀请好友完成目标行为 | 师傅、徒弟双向奖励 | 单向支出 |
| 权益售卖 | 付费购买权益包 | 券、卡、折扣等权益 | 先收后可退 |

### 1.3 目标

| 编号 | 目标 | 对应验收 |
| --- | --- | --- |
| G-01 | 两玩法共用同一套活动配置、资格决策、发奖、对账能力 | AC-01 |
| G-02 | 资金相关链路零资损、零超卖、零重复发奖/退款 | AC-03、AC-05、AC-06、AC-08 |
| G-03 | 已收款订单最终收敛为「履约成功」或「退款成功」 | AC-08 |
| G-04 | 关键接口满足第 9 章性能指标 | AC-09 |

### 1.4 范围边界

**本期包含**：平台公共能力（活动配置、资格决策、统一发奖、操作记录、可靠任务、对账补偿、查询）；裂变完整链路；权益售卖完整链路；运营配置接口与查询接口；监控指标与告警。

**本期不包含**：

| 不包含项 | 说明 |
| --- | --- |
| 连续包月、代扣签约 | 不涉及周期扣款 |
| 阶梯价、动态定价、优惠叠加 | 仅定价维度扩展 |
| 权益转赠、按核销进度部分退款 | 边缘场景 |
| 多城市统一商品模板 | 配置维度扩展 |
| 运营工作台前端 | 仅提供接口 |
| 分账、结算、发票 | 与核心链路无关 |
| 规则引擎可视化编排 | 以配置化规则替代 |

## 2. 全局说明

### 2.1 角色定义

| 角色 | 说明 |
| --- | --- |
| 运营 | 配置活动、商品、奖励规则，控制上下线 |
| 终端用户 | 参与活动、邀请好友、购买权益 |
| 客服 | 查询单据、发起退款、处置异常 |
| 业务方 | 通过接口接入玩法能力 |

### 2.2 通用约定

| 约定 | 内容 |
| --- | --- |
| 金额单位 | 分（整数），不使用浮点 |
| 时间 | 服务端时间为准，UTC+8，毫秒时间戳 |
| 归属判定 | 城市、渠道、身份、持有状态以服务端可信上下文为准，客户端传值仅作提示 |
| 幂等 | 所有有副作用的写操作必须携带幂等键，重复请求返回首次结果 |
| 响应结构 | 统一为 `{code, message, data, traceId}`，业务拒绝与系统异常使用不同 `code` |

### 2.3 字段类型约定

| 类型标记 | 含义 | 约束 |
| --- | --- | --- |
| ID | 唯一标识 | 字符串，≤64 字符 |
| Enum | 枚举 | 取值见对应枚举表 |
| Amount | 金额 | 非负整数，单位分 |
| Ts | 时间戳 | 毫秒，非负整数 |
| Bool | 布尔 | true / false |

### 2.4 错误码规范

错误码分三类，业务方与前端据此区分处理路径。

| 区段 | 类别 | 处理方式 |
| --- | --- | --- |
| `0` | 成功 | 正常返回 |
| `1xxx` | 业务拒绝（可预期） | 展示原因，不重试 |
| `4xxx` | 参数/校验错误 | 修正入参后重试 |
| `5xxx` | 系统异常（不可预期） | 可重试或降级 |

全局错误码见附录 C，功能特有错误码在各功能条目「异常处理」中列出。

## 4. 状态模型

本章集中定义跨功能引用的状态枚举，功能条目引用不重复定义。

### 4.1 活动状态

| 枚举值 | 含义 | 可咨询 | 可新建单据 | 已有单据处理 |
| --- | --- | --- | --- | --- |
| `DRAFT` | 草稿 | 否 | 否 | — |
| `SCHEDULED` | 待生效 | 否 | 否 | — |
| `ONLINE` | 进行中 | 是 | 是 | 正常 |
| `PAUSED` | 暂停 | 否 | 否 | 继续处理 |
| `ENDED` | 已结束 | 否 | 否 | 继续处理 |

流转：`DRAFT → SCHEDULED → ONLINE → ENDED`；`ONLINE ↔ PAUSED`。

### 4.2 裂变关系状态

| 枚举值 | 含义 | 前置状态 | 写入触发 |
| --- | --- | --- | --- |
| `INVITED` | 已邀请 | 无 | 师傅分享（FR-F05） |
| `CONNECTED` | 已建联 | `INVITED` | 徒弟点击落地页（FR-F05） |
| `JOINED` | 已加入 | `INVITED`/`CONNECTED` | 徒弟提交加入（FR-F06） |
| `DONE` | 已完成（终态） | `JOINED` | 完成后置处理（FR-F07） |
| `EXPIRED` | 已过期（终态） | 非终态 | 定时治理（FR-F09） |
| `CANCEL` | 已取消（终态） | 非终态 | 风控/人工 |

### 4.3 权益订单状态（三子状态并存）

业务主单以三个独立子状态并存表达，不使用单一状态字段。展示状态为派生结果，仅用于展示与筛选，不作为流转依据。

**支付子状态（pay）**

| 枚举值 | 含义 |
| --- | --- |
| `INIT` | 已创建，未发起支付 |
| `WAIT_PAY` | 待支付 |
| `PAYING` | 支付结果待确认 |
| `PAY_SUCCESS` | 支付成功（终态） |
| `PAY_FAILED` | 支付失败（终态） |
| `CLOSED` | 已关闭（终态） |

**履约子状态（grant）**

| 枚举值 | 含义 |
| --- | --- |
| `NOT_START` | 未开始 |
| `GRANTING` | 履约中 |
| `GRANT_SUCCESS` | 核心权益全部成功（终态） |
| `GRANT_FAILED` | 明确失败 |
| `GRANT_UNKNOWN` | 结果未知，待查单 |

**退款子状态（refund）**

| 枚举值 | 含义 |
| --- | --- |
| `NONE` | 无退款 |
| `REVOKING` | 权益回收中 |
| `REVOKE_FAILED` | 回收失败，待处置 |
| `REFUNDING` | 退款中 |
| `REFUND_SUCCESS` | 退款成功（终态） |
| `REFUND_FAILED` | 退款失败，待处置 |

**展示状态派生表**

| 展示状态 | 派生条件 |
| --- | --- |
| 待支付 | `pay ∈ {WAIT_PAY, PAYING}` |
| 已取消 | `pay ∈ {CLOSED, PAY_FAILED}` |
| 发放中 | `pay = PAY_SUCCESS` 且 `grant ∈ {NOT_START, GRANTING, GRANT_UNKNOWN}` |
| 已完成 | `grant = GRANT_SUCCESS` 且 `refund = NONE` |
| 退款中 | `refund ∈ {REVOKING, REFUNDING}` |
| 已退款 | `refund = REFUND_SUCCESS` |
| 异常 | `grant = GRANT_FAILED` 或 `refund ∈ {REFUND_FAILED, REVOKE_FAILED}` |

### 4.4 操作记录状态

| 枚举值 | 含义 | 可否重做 |
| --- | --- | --- |
| `INIT` | 已创建，未调用下游 | 可 |
| `PROCESSING` | 已调用，未收到终态 | 不可，须查单 |
| `SUCCESS` | 明确成功（终态） | — |
| `FAILED` | 明确失败 | 可按策略处理 |
| `UNKNOWN` | 结果未知 | 不可，须查单 |

### 4.5 发奖结果分类

发奖结果分为四类，各类处置方式不同，不得合并。「明确失败」与「未知」的区分为资金安全的核心规则，判定依据见 BR-C-10。

| 结果 | 定义 | 处理 |
| --- | --- | --- |
| SUCCESS | 下游明确返回已发放 | 更新成功 |
| FAILED | 下游确认未发放且不会转成功 | 按策略重试或走逆向 |
| PROCESSING | 下游已受理未完成 | 等待通知或主动查单 |
| UNKNOWN | 超时、断连、响应不可解析 | 主动查单，禁止直接判失败 |

## 5. 平台公共能力（功能详述）

> 玩法层不得重复实现本章能力。各功能条目采用统一结构：前置条件 / 输入 / 处理流程 / 输出 / 业务规则 / 异常处理 / 后置条件。

### FR-C01 活动管理

**前置条件**：操作者具备运营权限。

**输入（活动配置）**

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| activityId | ID | 系统生成 | 唯一 |
| name | String | 是 | ≤128 字符 |
| playType | Enum | 是 | `FISSION` / `BENEFIT_SELL` |
| scene | String | 是 | 用于场景路由 |
| status | Enum | 系统维护 | 见 4.1 |
| startTime / endTime | Ts | 是 | endTime > startTime |
| cityScope / channelScope | List | 否 | 为空表示不限 |
| crowdRule | Object | 否 | 人群规则 |
| riskRule | Object | 否 | 频控、黑名单、风险等级 |
| playConfig | JSON | 是 | 玩法私有配置，见 6.1 / 7.1 |
| configVersion | Int | 系统生成 | 每次发布递增 |

**处理流程**

1. 保存草稿或提交发布；
2. 发布前执行校验（见业务规则）；
3. 校验通过则生成不可变配置版本，`status → SCHEDULED`；
4. 到达生效时间由调度推进至 `ONLINE`。

**输出**：活动编号、配置版本号、当前状态。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-C-01 | 仅 `ONLINE` 且在有效期内的活动进入候选集 |
| BR-C-02 | `PAUSED`、`ENDED` 不影响已创建单据的后续处理 |
| BR-C-03 | 修改在线活动只能生成新版本，不得覆盖历史版本 |
| BR-C-04 | 发布校验：有效期合法、至少一项可用奖励或商品、供应方配置完整、人群/频控/风控可解析、玩法私有配置通过各自校验 |
| BR-C-05 | 创建业务单据时固化：活动编号 + 配置版本号 + 关键配置快照（奖励、价格、有效期、退款规则） |

**异常处理**

| 错误码 | 场景 |
| --- | --- |
| 4101 | 发布校验不通过 |
| 4102 | 有效期非法 |

**后置条件**：发布成功后活动进入 `SCHEDULED`，配置版本冻结。

### FR-C02 资格决策

**前置条件**：目标活动为 `ONLINE`。

**输入**：用户标识、场景、活动编号（可选）、客户端上下文（设备、IP、端、版本）。

**处理流程**

1. 构建可信上下文（身份、环境、归属、历史、状态、风险）；
2. 按资格规则组合判断；
3. 返回布尔结果与标准原因码。

**输出**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| pass | Bool | 是否通过 |
| reasonCode | Enum | 标准原因码 |
| context | Object | 用于后续步骤复用 |

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-C-06 | 客户端上传的城市、身份、持有状态仅作提示，最终以服务端上下文为准 |
| BR-C-07 | 结果必须含标准原因码，且区分「不符合条件」与「系统异常」 |
| BR-C-08 | 咨询阶段通过不代表创建单据时通过，创建时须重新校验关键条件 |

**异常处理**

| 错误码 | 场景 |
| --- | --- |
| 1201 | 不符合资格（业务拒绝，附 reasonCode） |
| 5201 | 上下文构建依赖异常 |

**后置条件**：无副作用（只读决策）。

### FR-C03 统一发奖

**前置条件**：玩法层已确定发奖对象与时机，已创建对应操作记录。

**输入（发奖请求）**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| playType | Enum | 是 | 路由与监控 |
| activityId | ID | 是 | |
| bizOrderNo | ID | 是 | 业务单据号 |
| opNo | ID | 是 | 操作单号，同时作为幂等键 |
| receiverId | ID | 是 | 接收用户 |
| rewardItems | List | 是 | 每项含类型、供应方商品标识、数量、是否核心 |

**处理流程**

1. 按 `opNo` 幂等校验；
2. 按供应方路由调用下游；
3. 按 4.5 分类结果；
4. 逐项记录状态并汇总。

**输出**：整体结果（4.5 分类）、每个奖励项独立状态、下游单号。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-C-09 | 同一 `opNo` 重复调用返回同一结果，不产生第二次发放 |
| BR-C-10 | 结果为 UNKNOWN / PROCESSING 时必须发起查单，禁止直接判 FAILED |
| BR-C-11 | 发奖、回收、退款三者幂等键不得复用 |
| BR-C-12 | 多奖励项时返回每项独立状态 |
| BR-C-13 | 支持按 `opNo` 主动查单与回收 |
| BR-C-14 | 玩法层不直接对接奖励供应方 |

**异常处理**

| 错误码 | 场景 |
| --- | --- |
| 5301 | 下游超时（判为 UNKNOWN，触发查单） |
| 5302 | 响应不可解析（判为 UNKNOWN） |

**后置条件**：操作记录状态更新为 4.4 之一；非终态挂载查单任务。

**业务规则**

### FR-C06 对账与补偿

**前置条件**：存在业务单据与操作记录。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-C-23 | 发现差异先查证，不直接覆盖状态 |
| BR-C-24 | 所有修复动作幂等 |
| BR-C-25 | 资损相关差异必须告警，并保留修复前后快照 |

**后置条件**：差异被修复或告警，留存审计。

### FR-F01 师傅进场

**前置条件**：用户已登录。

**业务规则**

| --- | --- |

**异常处理**：`1602` 已存在进行中轮次；`4602` 有效期超上限。

### FR-F04 好友过滤

**前置条件**：候选集大小在受控上限内。

**输入**：候选好友集合、活动上下文、邀请凭证。

**过滤规则（失败语义）**

| 编号 | 类别 | 判断 | 失败语义 |
| --- | --- | --- | --- |
| BR-F-07-a | 关系 | 是否已有进行中关系 | fail-close |
| BR-F-07-b | 分享频控 | 当天是否已收到同类分享 | fail-close |
| BR-F-07-c | 账户状态 | 是否注销或禁言 | fail-close |
| BR-F-07-d | 用户角色 | 是否为允许的用户类型 | fail-close |

**输出**：最终可用集合；按原因归类的拒绝集合；本次生效配置版本；本次降级规则清单。

**业务规则**

### FR-F06 徒弟加入

**前置条件**：徒弟已登录，邀请凭证有效。

**输入**：徒弟身份、终端信息、邀请凭证、外部业务号、外部流水号。

**处理流程**

1. 校验徒弟身份与终端；
2. 解密并校验邀请凭证；
3. 校验师徒非同一人；
4. 获取用户维度分布式锁；
5. 按外部业务号查询或创建操作记录（幂等）；
6. 定位关系：存在 `INVITED`/`CONNECTED` 则推进 `JOINED`；不存在按配置决定是否直建 `JOINED`；
7. 执行徒弟侧资格与风控校验；
8. 返回活动信息。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-F-14 | 外部业务号标识一次师徒关系，须与后续完成操作一致 |
| BR-F-15 | 外部流水号标识本次操作，用于幂等，与外部业务号不天然相等 |
| BR-F-16 | 同一徒弟并发加入只产生一条有效关系 |

**异常处理**：`1614` 师徒为同一人；`5614` 锁获取失败（阻断）。

**后置条件**：关系推进至 `JOINED`。

### FR-F07 徒弟完成与双向发奖

**前置条件**：关系状态为 `JOINED`。

**输入**：裂变组、徒弟标识、外部业务号、完成事件。

**处理流程**

1. 关系预处理：按裂变组、徒弟、业务号定位唯一关系，校验为 `JOINED`，关联操作记录；
2. 徒弟发奖：调用 FR-C03，更新发奖状态；
3. 师傅返奖：构造独立子流程，生成派生流水号，触发师傅奖励；
4. 轮次进度：进度 +1，达阶梯节点解锁阶段奖励；
5. 关系后处理：条件更新 `JOINED → DONE`。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-F-17 | 关系后处理使用条件更新（`WHERE status='JOINED'`），防止重复推进 |
| BR-F-18 | 轮次进度推进以关系标识或操作单号为幂等依据 |
| BR-F-19 | 同一完成事件重复执行生成相同的师傅返奖流水号；不同徒弟/轮次不冲突 |
| BR-F-20 | 师傅返奖失败不回滚徒弟已成功奖励，独立重试与告警 |
| BR-F-21 | 接口响应不单独返回师傅返奖状态，其结果由子流程保证 |

**异常处理**：`1617` 关系非 `JOINED`；师傅返奖失败进入可靠任务重试。

**后置条件**：关系为 `DONE`；徒弟发奖终态；师傅返奖由子流程收敛。

## 7. 权益售卖玩法（功能详述）

### 7.1 玩法私有配置

**商品配置**

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| skuId | ID | 唯一 |
| name / type | String / Enum | 单次权益包 / 月卡 |
| saleStatus | Enum | 可售 / 暂停 / 售罄 / 下线 |
| originPrice / salePrice | Amount | 划线价 / 售卖价，单位分，不为负 |
| benefitPackVersion | Int | 权益包版本 |
| benefitValidRule | Object | 权益有效期规则 |
| refundRule | Object | 退款规则 |
| stockRule / limitRule | Object | 库存 / 限购规则 |

**对象关系**：1 SKU → 1 权益包 → N 权益项；1 业务主单 → N 履约明细。SKU 含多个权益项时须按项记录状态。

**价格能力**：支持固定售卖价、首购特价、指定人群价、划线价展示、服务端试算；不支持阶梯价、动态价、优惠叠加。

**两层库存**

| 层 | 归属 | 平台保证 |
| --- | --- | --- |
| 营销库存 | 平台（活动总量、SKU 量、城市量、预算） | 0 超卖 |
| 供应方库存 | 外部（券码池、卡额度） | 平台不保证 |

库存时点：咨询只查不占；创建订单预占；支付成功预占转消耗；关闭/超时/失败释放。

**发布校验**：SKU 至少一个核心权益；所有权益项配置供应方与商品标识；价格不为负；金额为 0 的商品不走支付售卖链路；原子权益包中存在不可回滚权益时须配置异常处置策略；供应方库存须支持支付前锁定，否则不允许上线。

---

### FR-B01 预咨询与试算

**前置条件**：用户已登录。

**输入**：用户标识、场景、活动/商品编号（可选）、终端上下文。

**处理流程**

1. 查询有效活动候选集；
2. 过滤非在线、未开始、已结束活动；
3. 校验城市、渠道、场景；
4. 执行人群、频控、风控（FR-C02）；
5. 查询 SKU 售卖状态与库存；
6. 服务端计算用户实际价格；
7. 查询权益包可发放性；
8. 生成咨询凭证；
9. 返回。

**输出**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| activityId / skuId | ID | |
| configVersion | Int | 配置版本 |
| originPrice / dealPrice | Amount | 原价 / 成交价 |
| benefitSummary | Object | 权益包摘要 |
| buyableQty | Int | 可购数量 |
| qualifyResult / reasonCode | Object | 资格结果与原因码 |
| consultToken / expireTime | ID / Ts | 咨询凭证及有效期 |

**咨询凭证**：签名或服务端存储，绑定用户、活动与商品、成交价、配置版本、城市与渠道、过期时间。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-B-01 | 无可购商品为正常业务结果，与系统异常使用不同响应码 |
| BR-B-02 | 咨询通过不代表下单必然通过 |
| BR-B-03 | 成交价由服务端计算 |
| BR-B-04 | 下单时不信任客户端回传金额 |

**异常处理**：`1701` 无可购商品；`1702` 不符合资格。

**后置条件**：签发咨询凭证，无业务单据副作用。

---

### FR-B02 创建订单

**前置条件**：持有有效咨询凭证。

**输入**：咨询凭证、用户标识、商品编号、购买数量、客户端请求号。

**处理流程**

```
① 校验咨询凭证与用户、商品一致
② 重新校验活动状态、资格、限购、风控
③ 重新试算价格
④ 价格比对（见规则 BR-B-08）
⑤ 原子预占营销库存与用户购买额度
⑥ 创建业务主单 + 固化配置快照 + 创建操作记录     ← 事务一
⑦ 调用支付下单                                    ← 事务外
⑧ 保存支付单号与收银台参数，pay → WAIT_PAY        ← 事务二
```

**输出**：业务主单号、支付单号、收银台参数。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-B-05 | 业务幂等键 = 用户 + 活动 + 商品 + 客户端请求号，服务端唯一索引兜底 |
| BR-B-06 | 同一幂等请求返回同一主单与支付单，不重复预占库存 |
| BR-B-07 | RPC 调用不得包含在事务内；事务二失败依靠查单任务恢复 |
| BR-B-08 | 咨询价与重新试算价不一致时一律拒绝并返回专用错误码，前端刷新咨询；不取较低价、不静默使用新价 |
| BR-B-09 | 支付下单超时时查询支付结果，不得创建第二笔支付单 |
| BR-B-10 | 任一前置失败不得推进后续步骤，已预占库存须释放 |

**异常处理**

| 错误码 | 场景 | 处理 |
| --- | --- | --- |
| 1711 | 价格不一致 | 不创建订单，返回刷新提示 |
| 1712 | 库存预占失败 | 不创建支付单 |
| 5711 | 支付下单超时 | 查单恢复，不重复下单 |
| 5712 | 保存支付结果失败 | 查单任务恢复 |

**后置条件**：成功则 `pay = WAIT_PAY`，库存预占，操作记录存在。

---

### FR-B03 支付结果处理

**前置条件**：存在待支付主单。

**输入**：支付结果通知（签名、时间戳、支付单号、金额、币种、商户、结果）。

**处理流程**

```
① 验证签名、时间戳、防重放
② 按支付单号定位操作记录
③ 校验商户、金额、币种、主单归属
④ 锁定主单并校验当前状态
⑤ 幂等处理重复与乱序通知
⑥ 更新操作记录与支付状态
⑦ 库存预占转消耗
⑧ 写入履约可靠任务          ← ⑥⑦⑧ 同一事务
⑨ 返回确认
```

**支付结果映射**

| 支付结果 | 处理 |
| --- | --- |
| 成功 | `pay = PAY_SUCCESS`，异步触发履约 |
| 失败 | `pay = PAY_FAILED`，释放库存 |
| 处理中 | 保持并创建查单任务 |
| 已关闭 | `pay = CLOSED`，释放库存 |

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-B-11 | 实付金额与应付金额不一致不得推进状态并告警 |
| BR-B-12 | 未通过验签的通知不得更新任何业务状态 |
| BR-B-13 | 不得在通知处理中同步执行完整发奖 |
| BR-B-14 | 已支付订单不得被关闭 |
| BR-B-15 | 返回确认前本地状态与可靠任务必须已落库 |

**异常处理**：`4731` 验签失败；`1731` 金额不一致（告警）。

**后置条件**：`pay` 进入终态，履约任务已入库（成功场景）。

---

### FR-B04 订单关闭

**前置条件**：主单 `pay ∈ {INIT, WAIT_PAY, PAYING}`。

**触发**：用户放弃支付、收银台取消、超支付有效期、运营清理、定时任务。

**处理流程**

1. 校验状态可关闭；
2. 关闭前查询或调用支付关单，防止与支付并发；
3. 支付已成功则拒绝关闭并转支付成功处理；
4. 更新主单与操作记录；
5. 释放库存预占与购买额度；
6. 重复关单返回原结果。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-B-16 | 支付成功订单拒绝关闭 |
| BR-B-17 | 关闭与支付并发时以支付系统结果为准 |
| BR-B-18 | 重复关单幂等 |

**异常处理**：`1741` 订单已支付，拒绝关闭。

**后置条件**：`pay = CLOSED`，库存释放。

---

### FR-B05 权益履约

**前置条件**：`pay = PAY_SUCCESS`，金额校验通过，无进行中同类履约，未进入退款，权益快照完整。

**触发**：由支付成功事件经可靠任务自动触发，不依赖用户再次操作。

**处理流程**

1. 创建履约操作记录，`grant → GRANTING`；
2. 按权益快照生成履约明细；
3. 按供应方路由调用 FR-C03，以 `opNo` 为幂等键；
4. 记录供应方单号、状态、权益有效期；
5. 汇总各权益项状态；
6. 核心权益全部成功 → `grant = GRANT_SUCCESS`；失败或未知进入对应处置。

**发放策略**

| 策略 | 说明 | 主单结果 |
| --- | --- | --- |
| 原子发放 | 同一供应方一次性发放，全成或全败 | 直接使用下游终态 |
| 组合发放 | 按权益项分别调用 | 核心权益失败时已成功附加权益须回收或转人工；附加权益失败是否影响整体由配置决定 |

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-B-19 | RPC 超时不等于发放失败 |
| BR-B-20 | 未确认「权益未到账」前不得退款 |
| BR-B-21 | 发奖幂等键与退款幂等键不得复用 |
| BR-B-22 | 支付成功订单必须最终收敛 |
| BR-B-23 | `GRANT_FAILED` 不得由 RPC 超时直接触发，须经查单确认 |

**异常处理**：超时判 `GRANT_UNKNOWN` 并挂查单任务；核心权益失败进入 FR-B06。

**后置条件**：`grant` 收敛为 `GRANT_SUCCESS` 或进入失败处置。

---

### FR-B06 履约结果收敛

**前置条件**：存在处理中或未知履约结果。

**处理流程**

1. 接收供应方发放结果通知，验签并幂等处理；
2. 支持按主单号或供应方单号主动查单；
3. 对处理中与未知按退避策略查询；
4. 超时限告警；
5. 确认成功后更新履约明细与主单；
6. 确认失败后进入失败处置。

**失败处置策略（按商品配置）**：自动重试发放 / 回收已发附加权益后退款 / 仅补发失败权益项 / 转人工确认。

**默认策略**：核心权益明确失败 → 确认无权益到账 → 已发附加权益回收 → 自动原路退款。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-B-24 | 未知状态必须查单收敛，不得直接判失败 |
| BR-B-25 | 确认失败并确认无到账后方可进入退款 |
| BR-B-26 | 所有查单与处置幂等 |

**后置条件**：`grant` 进入终态。

---

### FR-B07 权益使用状态

**前置条件**：存在已履约主单。

**能力**：按订单查询权益有效期与使用状态；接收供应方核销通知（可选）；记录最近同步时间；退款前查询最新状态；无法查询时采用保守策略并转人工。

**状态枚举**：`UNUSED` / `PARTIALLY_USED` / `USED` / `EXPIRED` / `UNKNOWN`。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-B-27 | 退款前必须获取最新使用状态 |
| BR-B-28 | 使用状态无法确认时采用保守策略并转人工 |

**后置条件**：使用状态可供退款准入判定。

---

### FR-B08 退款准入与权益回收

**前置条件**：`pay = PAY_SUCCESS`。

**退款来源**：用户主动、客服操作、履约失败自动退款、对账发现已支付未履约、供应方故障批量退款。

**准入校验**：支付成功；无成功退款；无进行中退款；可退金额 > 0；发放状态已确认（不得在未知状态下退款）；使用状态已确认；已发权益支持回收；退款原因与来源合法。

**处理顺序**

| 场景 | 顺序 |
| --- | --- |
| 权益从未发放 | 直接退款 |
| 已发放且可回收 | 先回收成功，再退款 |
| 已部分使用 | 按规则拒绝、部分退或转人工 |
| 状态未知 | 先查权益状态，不得直接退款 |
| 不可回收 | 按商品规则拒绝或走审批 |

**回收与核销并发**：回收请求携带「仅当未使用时回收」语义，由供应方原子判定并返回实际状态；前置查询仅用于提示与准入初筛。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-B-29 | 不得在发放未知状态下退款 |
| BR-B-30 | 已发放且可回收权益须先回收成功再退款 |
| BR-B-31 | 回收使用独立幂等键 |
| BR-B-32 | 记录每个权益项回收结果 |
| BR-B-33 | 回收失败不得直接推进退款，除非业务明确接受资损 |
| BR-B-34 | 回收与退款先后顺序可审计 |

**异常处理**：`1781` 不满足准入；`1782` 权益已使用，拒绝退款；`5781` 回收失败（`refund = REVOKE_FAILED`，转处置）。

**后置条件**：满足准入且回收完成后进入 FR-B09。

---

### FR-B09 退款执行

**前置条件**：通过 FR-B08 准入，回收已完成（如需）。

**处理流程（申请）**

1. 创建独立退款操作记录，生成唯一退款单号；
2. 锁定主单，`refund → REFUNDING`；
3. 同事务写入退款执行任务；
4. 异步调用支付退款；
5. 保存受理结果与支付侧退款单号。

**回调处理**：验签防重放 → 定位退款操作记录 → 校验主单、原支付单、金额、商户 → 锁定主单 → 幂等更新 → 记录完成时间 → 投递事件。

**业务规则**

| 编号 | 规则 |
| --- | --- |
| BR-B-35 | 退款接口返回「受理成功」仅表示请求已接收 |
| BR-B-36 | 只有回调或查单确认才能进入 `REFUND_SUCCESS` |
| BR-B-37 | 调用超时使用原退款单号查单或重试 |
| BR-B-38 | 禁止超时后生成新退款单号重复退款 |

**异常处理**：`5791` 退款超时（原单号查单）；退款失败 `refund = REFUND_FAILED` 转处置。

**后置条件**：`refund` 收敛为 `REFUND_SUCCESS` 或进入失败处置。

## 8. 数据一致性专项要求

### 8.1 四层防线

| 层 | 机制 | 防范 | 单独充分 |
| --- | --- | --- | --- |
| 1 | 凭证签名 | 参数伪造、越权 | 否 |
| 2 | 分布式锁 | 并发碰撞 | 否 |
| 3 | 业务唯一键 + 唯一索引 | 重复创建 | 否 |
| 4 | 操作记录 + 可靠任务 | 中断、未知、重放 | 最终保证 |

资金相关操作必须依赖第 3、4 层，锁仅降低碰撞概率不保证幂等。

### 8.2 幂等键规划

| 场景 | 幂等键 | 唯一约束位置 |
| --- | --- | --- |
| 创建业务单 | 用户 + 活动 + 商品 + 请求号 | 操作记录 |
| 支付下单 | 操作单号 | 支付系统 |
| 支付通知 | 支付单号 + 状态 | 操作记录 |
| 发奖 | 操作单号 | 发奖能力 |
| 师傅返奖 | 由徒弟操作单号派生 | 操作记录 |
| 退款 | 独立退款单号 | 支付系统 |
| 权益回收 | 独立回收单号 | 发奖能力 |
| 可靠任务 | 业务单号 + 任务类型 | 任务表 |
| 关系创建 | 裂变组 + 师傅 + 徒弟 | 关系表 |

发奖、回收、退款三者幂等键不得复用。

### 8.3 典型失败场景处理

| 场景 | 处理 |
| --- | --- |
| 发奖成功，状态更新失败 | 不重发，恢复到后处理步骤 |
| 徒弟发奖成功，师傅返奖失败 | 独立重试与告警，不影响徒弟奖励 |
| 下游成功，本地超时 | 原幂等键查单，不创建第二笔 |
| 锁获取失败 | 发钱操作在无其他强幂等保证时不放行 |
| 支付成功后进程中断 | 重启后由可靠任务与对账恢复 |
| 关系完成但进度未推进 | 重放幂等后处理，而非重发奖 |

### 8.4 读写侧职责

读侧过滤剔除重复对象用于改善体验与降低无效请求；「不允许重复建立有效关系」的最终不变量由写侧唯一约束、条件更新、业务幂等键、并发控制保证。

## 10. 验收标准

| 编号 | 验收项 | 验收要点 |
| --- | --- | --- |
| AC-01 | 配置 | 可创建活动并绑定商品与奖励；配置不完整禁止发布；发布后生成不可变版本；历史单据使用创建时快照 |
| AC-02 | 资格与咨询 | 不同条件得到不同资格结果并附原因码；返回服务端成交价；篡改咨询金额或商品后下单被拒 |
| AC-03 | 下单与库存 | 重复请求只创建一笔主单与支付单；并发下单不突破限购；500 并发抢 100 库存成功订单恰好 100；失败或关闭后释放预占 |
| AC-04 | 支付 | 合法通知推进状态并生成履约任务；重复与乱序通知不重复生成任务；金额不一致与验签失败不推进状态；支付与关单并发结果与支付系统一致 |
| AC-05 | 履约 | 支付成功后无需用户操作即可发放；重试不产生重复权益；组合权益可查每项状态；RPC 超时进入未知态查单不直接退款；核心权益全成后进入成功态 |
| AC-06 | 退款 | 未发权益可退；已发且可回收权益回收成功后退款；已使用权益按规则拒绝或转人工；同订单最多一笔有效退款；退款受理不被误判为成功 |
| AC-07 | 裂变链路 | 师傅可进场获取凭证与轮次；过滤剔除已有进行中关系用户；分享创建 `INVITED`、点击推进 `CONNECTED`、加入推进 `JOINED`；完成后双方获奖，关系推进至 `DONE`；同一徒弟并发加入只产生一条关系；过期关系被推进至 `EXPIRED` |
| AC-08 | 对账与补偿 | 支付成功但本地缺失可自动恢复；无履约任务的已支付订单可补建；通知丢失可查单收敛；进程中断重启后收敛率 100%；所有自动修复有操作记录与审计 |
| AC-09 | 可观测 | 一次请求可通过任意标识双向追踪；可看好友过滤候选数/通过数/拒绝原因分布；可看操作记录状态变化；可关联业务单据与奖励单号；可区分业务拒绝、配置错误、系统错误 |

## 11. 附录

### 附录 A：两玩法对照

| 维度 | 裂变 | 权益售卖 |
| --- | --- | --- |
| 发奖凭证 | 徒弟完成目标行为 | 用户支付成功 |
| 资金方向 | 单向支出 | 先收后可退 |
| 发奖对象 | 2 人（师傅 + 徒弟） | 1 人（买家） |
| 逆向链路 | 几乎没有 | 完整退款 + 回收 |
| 明细数量 | 无自然上界 | 少量（几个权益项） |
| 核心风险 | 刷量、重复发奖 | 资损（钱货不一致） |
| 核心难点 | 热点数据与查询放大 | 跨系统最终一致性 |

### 附录 B：不合并的对象

| 对象 | 裂变 | 权益售卖 |
| --- | --- | --- |
| 参与实例 | 裂变组（一轮邀请） | 业务主单（一次购买） |
| 明细 | 裂变关系（每个徒弟） | 履约明细（每个权益项） |

两类对象形状相似但膨胀特征、索引、分页、归档策略不同，各自独立，通过玩法类型与操作记录关联。
